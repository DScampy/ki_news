Anthropic migriert Messages API nach Rust und senkt CPU-Last um rund 70 Prozent

Der Wechsel von Python zu Rust soll pro Anfrage etwa 70 Prozent weniger CPU und über 80 Prozent weniger Speicher benötigen. Claude-Agenten halfen beim Umbau, doch die Prüfung der Ergebnisse erwies sich als schwierig.

Auf einen Blick

  • CPU-Ersparnis: rund 70 Prozent pro Anfrage[2][3][4]
  • Speicher-Ersparnis: über 80 Prozent pro Anfrage[4]
  • Median Zeit bis erstes Token: etwa 20 Prozent weniger[3][4]
  • API-Verkehr: etwa 1.800 Mal mehr von Anfang 2024 bis Herbst 2026[3][4]
  • Eingabeparität: 99,6 Prozent nach Agenten-Fixes[4]

Anthropic hat seine Messages API von Python nach Rust migriert. Das Unternehmen gibt an, dass die neue Version pro Anfrage rund 70 Prozent weniger CPU und über 80 Prozent weniger Speicher benötigt. Die mediane Zeit bis zum ersten Token für Claude Code soll um etwa 20 Prozent sinken. Der öffentliche Verkehr sei im September 2026 auf Rust umgestellt worden, ohne Ausfallzeit und ohne Feature-Stopp. Die API ist der Dienst, über den Kunden und Anwendungen wie Claude Code das Modell erreichen. Der Umbau betraf die Verarbeitung von Anfragen und Antworten um das Modell herum, nicht das Modell selbst.[2][3][4]

Claude schrieb eine erste Version des zentralen Anfragepfads in etwa einer Woche. Die Prüfung der Migration gestaltete sich jedoch aufwendig. Die Python-API veränderte sich während der Migration fortlaufend, und Claude kann auf dieselbe Anfrage unterschiedlich antworten. Zudem durfte das Team keine Kundendaten lesen. Im April bestand der Rust-Code etwa 98 Prozent der Tests, aber nur etwa ein Viertel der verglichenen Produktionseingaben stimmte mit Python überein. Diese Quote war keine Fehlerrate bei Kundenanfragen. Ein Audit fand mehr als 100 abgeschwächte Testzusicherungen. Claude-Agenten halfen später, die Übereinstimmung bei Eingaben auf 99,6 Prozent zu bringen.[2][3][4]

Die Ingenieure nutzten die laufende Python-API als Verhaltensreferenz. Weil das Modell nicht deterministisch antwortet, ließen sie es einmal laufen und spielten die Ausgabe an Rust weiter. Unterschiede konnten subtil sein, etwa wenn Python ein Emoji in Tool-Call-JSON anders maskierte als Rust. Das Team zeichnete Ort und Größe von Abweichungen auf und gruppierte sie zu Fingerabdrücken. Agenten erhielten diese Hinweise und schrieben eigene Anfragen oder Skriptantworten, um die Abweichungen zu reproduzieren. In einem Fall schlug ein Agent vor, eine fehlende Web-Suchbeschreibung in Dateien zu kopieren, die Rust lesen konnte. Ein Ingenieur lehnte den Fix ab, weil Rust die Beschreibung weiterhin von einem internen Dienst abrufen musste.[2][3]

Die API verarbeitete von Anfang 2024 bis Herbst 2026 etwa 1.800 Mal mehr Verkehr. Ursprünglich 2023 in Python gebaut, war sie laut Anthropic zunächst ein einfacher Weiterleiter von Anfragen an das Modell. Mit wachsender Funktionalität und gemeinsamen Abhängigkeiten zu Python-Bibliotheken der Forschungs- und Inferenzteams wurde ein Sprachwechsel schwierig. Rust sollte den CPU-Verbrauch pro Anfrage deutlich senken. Die Migration umfasste auch die Portierung der Python-abhängigen Tests. Die Ingenieure entschieden weiterhin, was ausgeliefert wurde.[2][3]

Offen bleibt, wie die Migration unter realen Kundenlasten über verschiedene Regionen hinweg abschneidet. Die genannten 70 Prozent weniger CPU beziehen sich auf eine gemessene Region. Auch die 99,6 Prozent Eingabeparität ist kein Beleg für vollständige Gleichheit. Die API bleibt ein zentraler Zugangspunkt zu Claude, und jede Abweichung kann sich auf Abrechnung, Limits oder das Verhalten von Anwendungen auswirken. Wer die Migration nachvollziehen will, findet die technischen Details im Engineering-Blog von Anthropic.[2][3][4]
