Manipulierte Claude-Code-Erweiterung im Cursor-Marktplatz betraf bis zu 5000 Nutzer

Version 2.1.313 der Erweiterung Claude Code for VS Code enthielt eine SSH-Backdoor. Laut Cursor sind höchstens 5000 Nutzer betroffen. Wie die Angreifer ins Konto kamen, ist unklar.

Im Cursor-Marktplatz war die offizielle Erweiterung Claude Code for VS Code mit einer SSH-Backdoor versehen. Die manipulierte Version 2.1.313 betraf laut Cursor „at most 5,000 users“. Heise nennt unter Berufung auf Reuters ebenfalls bis zu 5000 Nutzer. Eine bereinigte Fassung ist verfügbar, Admins sollten mindestens auf Version 2.1.314 aktualisieren.[1][2]

Die Version lief laut Heise nach Angaben von Cursor zwischen 10:27 und 21:35 Uhr mitteleuropäischer Zeit am Donnerstag im Marktplatz. Ars Technica spricht von fast 12 Stunden. Anthropic lieferte laut dem unabhängigen Forscher Kevin Beaumont einige Stunden nach der schädlichen Version die Fassung 2.1.314 aus. Cursor-Erweiterungen aktualisieren sich standardmäßig automatisch, was in den Einstellungen änderbar ist.[1][2]

Unklar ist die Herkunft. Luke Roberts (CTO und Mitgründer Phorion) sagt, die Version sei über den offiziellen Anthropic-Account verteilt worden und habe 2.1.312 ersetzt. Heise zitiert dagegen Cursor mit der Aussage, die Version stamme nicht von Anthropic. Wie die Angreifer die Kontrolle über das Konto erlangten, haben laut Ars Technica weder Cursor noch Anthropic erklärt.[1][2]

Laut Cursor versucht die Erweiterung, eine dauerhafte SSH-Hintertür einzurichten. Dafür dient ein Schlüssel der Angreifer, der lokale SSH-Dienst wird aktiviert und ein Reverse-SSH-Tunnel geöffnet. Der Code läuft auf Windows, macOS und Linux, Cursor nennt manipulierte Pakete für macOS und Windows. Da Erweiterungen mit den Rechten der IDE laufen, sind lokale Dateien, Quellcode und Entwickler-Tools erreichbar. Phorion zufolge half der Diebstahl von Variablennamen, Cloud-Zugangsdaten und API-Tokens zu inventarisieren.[1][2]

Ein Logikfehler verhinderte laut Heise meist die Aktivierung von SSH unter macOS, weil der Befehl ohne Admin-Rechte keinen „Off“-Status liefert. Dennoch legt die Malware Schlüssel ab, nistet sich ein und meldet Rechnerdaten an die Angreifer. Phorion nennt sie weiterhin eine erhebliche Bedrohung. Deinstallieren genügt nicht: Tunnel-Prozesse beenden, Persistenz entfernen und den Schlüssel „svc-telemetry“ aus „~/.ssh/authorized_keys“ löschen.[1][2]

Offen bleibt, wie der Account übernommen wurde und warum Anthropic Kunden laut Ars Technica bislang nicht öffentlich warnte. Wer die Version 2.1.313 installiert hatte, sollte die Bereinigung nach Phorions Anleitung durchführen und gespeicherte Cloud-Zugangsdaten sowie Tokens prüfen. Golem spricht von Tausenden betroffenen Systemen und von millionenfach installierter Erweiterung, die tatsächliche Betroffenenzahl nennt aber nur die 5000-Obergrenze.[1][2][3]
